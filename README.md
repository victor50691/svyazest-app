# Связь Есть?

[![Build APK](https://github.com/victor50691/svyazest-app/actions/workflows/build.yml/badge.svg)](https://github.com/victor50691/svyazest-app/actions/workflows/build.yml)

Android-приложение для сети [DPI//Checker](https://t.me/dpi_checker_robot):
превращает ваш телефон в «исполнителя», который выполняет короткие проверки
доступности VPN-ключей (VLESS / VMESS / TROJAN / SHADOWSOCKS / HYSTERIA2) и
IP-адресов/доменов прямо со своих мобильных данных, и получает за это
вознаграждение на баланс в Telegram-боте [@svyaz_estt_bot](https://t.me/svyaz_estt_bot).

Проверки идут напрямую с реального мобильного соединения конкретного
оператора и региона — это единственный способ увидеть, что на самом деле
происходит с VPN-ключом или сайтом во время шейпинга/белых списков, а не
поведение через купленный прокси-пул. Заодно это единственный способ
проверить Hysteria2 (работает по UDP) — обычная проверка через прокси-пул
этого не умеет.

## Как это работает

1. Установите приложение и введите код, который выдаёт бот
   [@svyaz_estt_bot](https://t.me/svyaz_estt_bot) после регистрации
   (либо подтвердите вход одной кнопкой прямо в боте — приложение
   в это время ждёт подтверждения).
2. Включите тумблер «Работать» на главном экране — запускается foreground
   service с постоянным уведомлением о статусе (онлайн / нет моб. данных /
   выполняется проверка).
3. Пока включены мобильные данные, приложение по очереди забирает задания
   с сервера (long-poll), выполняет их и отправляет результат.
4. Баланс и история заданий видны и в приложении, и в боте.

Полный путь одной проверки:

```
пользователь DPI//Checker           ваш телефон                   заказчик
        |                                |                            |
   отправляет ключ/IP  --> очередь --> GET /jobs/poll (long-poll)     |
   в @dpi_checker_robot                 |                             |
                                  проверка с мобильных данных         |
                                  (Xray-core в процессе приложения    |
                                   или чистый TCP/TLS для IP)         |
                                        |                             |
                                  POST /jobs/:id/result --> бот присылает отчёт -->
                                        |
                                  вам начисляется вознаграждение
```

Приложение **не работает без мобильных данных** — при Wi-Fi-only или
отсутствии сети задания не назначаются, о чём явно сообщает уведомление
и главный экран. Это не прихоть: смысл сети в том, что проверка идёт
именно через сотового оператора в конкретном регионе.

## Установка

- Готовый APK — во вкладке [Releases](../../releases). Требуется
  **Android 7.0+ (minSdk 24)**, архитектура **arm64-v8a**.
- Либо соберите сами — см. [Сборка из исходников](#сборка-из-исходников).
  Исходники открыты ровно для этого: чтобы можно было проверить, что
  приложение делает с телефоном, и собрать его своими руками.

Приложение **не работает на устройствах с root** — см.
[FAQ](#почему-приложение-не-запускается-на-root).

## Что приложение делает с телефоном

Полный список разрешений из `AndroidManifest.xml` и зачем каждое:

| Разрешение | Зачем |
| --- | --- |
| `INTERNET` | сами проверки и общение с API |
| `ACCESS_NETWORK_STATE` | понять, есть ли мобильные данные, и найти сотовый интерфейс |
| `CHANGE_NETWORK_STATE` | привязать сокеты проверки к сотовой сети |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC` | фоновая работа с постоянным уведомлением |
| `POST_NOTIFICATIONS` | само уведомление о статусе |
| `WAKE_LOCK` | не засыпать в момент выполнения проверки |
| `RECEIVE_BOOT_COMPLETED` | вернуться в работу после перезагрузки телефона, если тумблер был включён |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | по желанию отключить агрессивное усыпление, иначе задания теряются |

Чего приложение **не** просит и не делает: нет доступа к контактам, SMS,
геолокации, файлам, камере и микрофону; нет своего VPN-туннеля на
устройстве (`VpnService` не используется вообще); нет рекламы и трекеров.

## Приватность: какие данные уходят на сервер

- **При привязке (`POST /pair`)** — модель устройства, версия Android,
  версия приложения и стабильный идентификатор установки (HWID) для
  привязки аккаунта к одному телефону.
- **Периодически (`POST /heartbeat`, `POST /network-report`)** — статус
  «онлайн/оффлайн», включены ли мобильные данные, название оператора,
  страна сети и SIM, признак «включён сторонний VPN», а также публичный
  IP, который сервер видит у запроса, отправленного через сотовую сеть.
  Это то, из чего строится карта «где и у кого сейчас глушат», и то, чем
  модератор проверяет, что телефон действительно в заявленном регионе.
- **По каждому заданию (`POST /jobs/:id/result`)** — результат проверки:
  успех/ошибка, задержка, коды ответа. Сам VPN-ключ приходит от сервера
  и живёт только в памяти процесса + во временном конфиге Xray, который
  удаляется после проверки.
- **Единственный секрет на устройстве** — `device_token`, он лежит в
  Android Keystore через `flutter_secure_storage`
  (`lib/services/secure_store.dart`).

Через ваше соединение ходит **только трафик проверок**, которые заказали
пользователи DPI//Checker (подключение к хосту ключа или к
проверяемому IP/домену), и ничего больше. Приложение не является
прокси/exit-нодой: оно не принимает и не пересылает чужой
пользовательский трафик.

## Как устроено технически

- **Flutter/Dart**, `minSdkVersion 24` (Android 7.0+), `targetSdk 36`.
- Постоянная работа в фоне — через
  [`flutter_foreground_task`](https://pub.dev/packages/flutter_foreground_task)
  (persistent notification + отдельный background isolate), а не через
  тяжёлый постоянный VPN-туннель. Цикл опроса заданий —
  `lib/services/executor_task_handler.dart`: свой `while`-цикл с
  long-poll на 25–40 секунд вместо тика по таймеру.
- **Проверка IP/домена** — обычное TCP/TLS-соединение средствами
  `dart:io` (`lib/services/checkers/ip_checker.dart`), без сторонних
  бинарников; отдельно разбирается цепочка редиректов
  (см. `test/redirect_chain_test.dart`).
- **Проверка VPN-ключа** — [Xray-core](https://github.com/XTLS/Xray-core)
  вкомпилирован в приложение как gomobile-библиотека
  (`android/app/libs/xraylib.aar`, собирается из `xraylib/`). Приложение
  поднимает локальный HTTP-прокси поверх тестируемого ключа, ходит через
  него на тестовый URL и измеряет результат/задержку. Ссылка ключа
  разбирается в `lib/services/vpn_uri_parser.dart`, конфиг Xray
  собирается в `lib/services/build_xray_config.dart`.
- **Проверка идёт именно через мобильную сеть**, даже если на телефоне
  включён сторонний VPN пользователя: каждый сокет, который открывает
  Xray, проходит через `internet.RegisterDialerController` и биндится
  на сотовый интерфейс через `android.net.Network.bindSocket()` — см.
  `socketBinder` в `android/.../NativePlugin.kt`. Именно ради этого Xray
  живёт внутри процесса приложения, а не отдельным процессом: дочерний
  процесс к сотовой сети не привяжешь. Подробности — в
  `third_party/xray-core/README.md`.
- **Android Key Attestation** (`lib/services/attestation.dart`) —
  при каждом запуске генерируется ключ в secure hardware с серверным
  nonce, цепочка уходит на проверку. Так сеть отличает живой телефон
  от эмулятора, который «проверяет» ключи, не выходя в сотовую сеть.
- **Backend** — `lib/services/api_client.dart` ходит в `/executor/v1/*`:
  отдельный сервис, исходники которого сюда не входят (закрытая часть
  инфраструктуры DPI//Checker). URL бэкенда не секрет и задаётся
  сборочным флагом:

  ```bash
  flutter build apk --release --dart-define=API_BASE_URL=https://your-host/executor/v1
  ```

  Без флага используется `https://dpichecker.st/executor/v1`.

## Структура проекта

```
lib/
  main.dart                     точка входа + регистрация background isolate
  theme.dart                    тема оформления
  screens/                      экраны: вход, главный, история, настройки,
                                гайд по обходу, экраны блокировки
  services/
    api_client.dart             клиент /executor/v1 (pair, poll, result, ...)
    executor_task_handler.dart  цикл работы в фоновом изоляте
    native_bridge.dart          мост в Kotlin (сотовая сеть, Xray, attestation)
    vpn_uri_parser.dart         разбор vless://, vmess://, trojan://, ss://, hy2://
    build_xray_config.dart      сборка конфига Xray по разобранному ключу
    checkers/                   сами проверки: ip_checker, vpn_checker
    attestation.dart            Android Key Attestation
    secure_store.dart           device_token в Keystore
    session_guard.dart          обработка 401/403 (разлогин, бан)
android/app/src/main/kotlin/... нативная часть: биндинг на сотовую сеть,
                                запуск Xray, attestation
xraylib/                        Go-обёртка Xray-core -> xraylib.aar (gomobile)
third_party/xray-core/          лицензия и пояснение про встроенный Xray
test/                           виджет-тесты и тест разбора цепочки редиректов
```

## Сборка из исходников

```bash
flutter pub get
flutter build apk --release
```

Понадобится Flutter (stable) и Android SDK с `platform-tools`,
`platforms;android-36`, `build-tools;36.0.0`. Для дебаг-сборки без своего
ключа подписи достаточно `flutter build apk` — соберётся ключом отладки.

`android/app/libs/xraylib.aar` лежит в репозитории готовым, поэтому для
обычной сборки Go и gomobile не нужны. Пересобрать библиотеку из
исходников Xray-core можно через `xraylib/build.sh` (нужны Go и
`gomobile`); версия и коммит Xray-core зафиксированы в
`third_party/xray-core/README.md`.

## Сборка подписанного релиза

```bash
keytool -genkeypair -v -keystore android/keystore/release.jks -alias <alias> \
  -keyalg RSA -keysize 2048 -validity 10000
```

Создайте `android/key.properties` (он в `.gitignore`, никогда не
коммитится):

```properties
storePassword=...
keyPassword=...
keyAlias=...
storeFile=../keystore/release.jks
```

## Тесты и CI

```bash
flutter analyze
flutter test
```

GitHub Actions (`.github/workflows/build.yml`) на каждый push и PR
прогоняет `analyze`, `test` и релизную сборку APK — без ключей подписи,
то есть собранный в CI APK подписан отладочным ключом и годится только
для проверки того, что проект собирается с чистого клона.

## FAQ

### Приложение работает, если у меня включён свой VPN?

Да. Проверки принудительно биндятся на сотовый интерфейс мимо вашего
VPN. Но на отдельных прошивках поведение может отличаться, поэтому,
если приложение видит активный сторонний VPN, оно честно предупреждает
об этом в интерфейсе.

### Почему приложение не запускается на root

На устройстве с root можно подменить сетевой стек и выдать фальшивый
результат проверки (см. `lib/screens/root_blocked_screen.dart`) — а вся
ценность сети именно в том, что результаты настоящие. Поэтому root
блокируется.

### Сколько это ест батареи и трафика?

В простое приложение висит на long-poll-запросе (одно HTTP-соединение,
25–40 секунд на цикл) и не делает ничего больше. Расход трафика — сами
проверки: единицы мегабайт в день при обычной нагрузке. Чтобы задания
не терялись, приложение предлагает отключить для себя оптимизацию
батареи — на главном экране, при включении тумблера «Работать».

### Меня заблокировали / разлогинило само

`401` — аккаунт занят другим устройством или устройство отвязано в
панели; `403` — бан устройства по HWID или бан аккаунта. Обработка — в
`lib/services/session_guard.dart`, вопросы — через бота.

### Почему собран только arm64-v8a?

Библиотека Xray собирается gomobile под `android/arm64`. На 32-битном
устройстве проверки VPN-ключей вернут ошибку архитектуры; проверки
IP/доменов чисто на Dart и работают везде.
